# Moving: the same keys, look, theme and tooltips in every app (task 17)

Task 17 removes no name of the package. It adds `LOOK_SMOOTH`, `LOOK_ONI`, `THEME_SYSTEM`, `THEME_LIGHT`, `THEME_DARK`,
`AppearanceOptions`, `AppOptions.appearance` and the type `FooterEntry` (all in `@acaprino/imago/ui`), and it changes
what some calls take or do. Each row is what an app may still write or rely on, with what to write or expect instead.

| Old name | New name, or what to do instead |
|---|---|
| A command of the app bound to `Escape` that also ran when the same Escape closed the inspector, the sidebar drawer, a menu, a sheet, a dialog or the palette | A key is answered once. `registry.attach` runs no command for a key whose default another handler already prevented, and the package's handlers of Escape prevent it when they close something. The app's Escape command runs on the next Escape, which nothing else takes. A command that relied on running after the inspector closed calls what it needs itself |
| An app's own handler that prevents the default of a key, then expects the command bound to that key to run as well | The command does not run: the handler that prevented the key has answered it. Leave the default alone in the handler, or run the command from it |
| A command bound to an arrow, `Home`, `End` (or, in a list with `onSelect`, `Space` or `Enter`) that also ran while focus was on an item of a `roving` list | The list moves (or selects) and the command does not run: `roving` prevents the default of the keys it acts on. Bind the command to another key, or let it run from outside the list |
| An app's own handler (on the window, while capturing) that prevents the default of Escape, then expects the top layer to close as well | The layer stays: `attachLayers` closes nothing for an Escape that is already taken |
| A held Escape in the inspector that closed every view pushed with `push` | One view per press, as one layer per press. The repeats of a held key are still the inspector's: they run no command |
| `mountApp` attaching the registry before the sidebar drawer and the fold | The drawer and the fold are attached before the registry, after the layers: an Escape that closes the drawer runs no command. The order of `register` calls and of the undo is unchanged |
| The errors of `mountApp`, which were the registry's own message (`Command "imago.palette" is already registered`, `Keys "Ctrl+K" of "imago.palette" are already bound to "open"`) | The same message after `mountApp: `, with the registry's error as its `cause`. Every error that `mountApp` or the function it returns throws starts with `mountApp: ` |
| The app's own commands, controls or Settings view to pick the look (Smooth, ONI) and the theme (follow Windows, light, dark) | `mountApp(shell, registry, { …, appearance: { get, set, labels } })`. It registers five palette commands, alike in every app: `imago.look.smooth`, `imago.look.oni`, `imago.theme.system`, `imago.theme.light`, `imago.theme.dark`, in the group `Appearance`, titled `Smooth look`, `ONI look`, `Follow Windows`, `Light theme`, `Dark theme` (an app in another language passes `labels`). No key is bound. The command of the current choice is not offered. The app keeps the choice where it keeps it today, gives it back in `get`, and in `set` stores it and calls `applyLook`; the package stores nothing. Remove the app's own commands with those ids, or `mountApp` throws |
| `footerKeys(doc, registry, ids)` | `footerKeys(doc, registry, entries)`: an entry is a command id, as before, or `{ keys, title }` for a key of a list that is not a command (the arrows, Space, Enter). `keys` is in the grammar of a command's keys; several bindings are separated by a space (`'ArrowUp ArrowDown'`). A footer key list written by hand (`<kbd class="im-key">↑↓</kbd>move`) goes through `footerKeys` |
| `WindowButtonLabels` with `minimize`, `maximize`, `close` | `windowButtonsHtml` (and `titlebarHtml`'s `windowControls`) also writes a `title` on each button, `Minimize`, `Maximize` and `Close` by default. The labels object gains three required words, `minimizeTitle`, `maximizeTitle`, `closeTitle`: an app that passes its labels passes the three tooltips too |
| `formHeaderHtml(title, subtitle, locked, id)`, its close button named `Close` with no tooltip | `formHeaderHtml(title, subtitle, locked, id, closeLabel)`: `closeLabel` (default `Close`) is the close button's `aria-label` and its `title`. An app in another language passes its word |
